The Reference section is for looking things up: exact names, signatures, routes, defaults, and codes. Most of it
is generated from the repository by `apps/docs/scripts/generate.mjs`, so it matches the code it documents: method
names and signatures come from the built TypeScript declarations and a live `betterIam()` instance, error codes from
every `IamError` thrown in `packages/*/src`, CLI usage from the CLI's own help text, and packages from the workspace
manifests. The Options page is written from `packages/server/src/options.ts` and the option types it imports.

## Machine-readable docs

The site serves its content for tools and language models as well as for people:

| URL | Content |
| --- | --- |
| `/llms.txt` | An index of every page with its description |
| `/llms-full.txt` | Every page as Markdown in one file |
| `/skills/better-iam/SKILL.md` | An agent skill for coding agents ([Agent skills](/docs/ai/agent-skills)) |
| `/docs/<page>.md` | One page as Markdown (also served for `Accept: text/markdown`) |
| `/api/search?query=…` | The search index behind the search dialog, as JSON |
| `/api/mcp` | An MCP server with search, page, API-method, export, and error-code tools; see [Use the docs with AI](/docs/ai) |
| `/openapi.json` | The OpenAPI 3.1 description of the HTTP API |

## Regenerating

```bash
pnpm build                                  # declarations the API catalog is read from
pnpm --filter @better-iam/docs generate     # data + generated pages (API, exports, errors, CLI, glossary)
node apps/docs/scripts/check-content.mjs    # validate every page and link
```

See [Contributing](/docs/reference/contributing#documentation-site) for every generator step.
