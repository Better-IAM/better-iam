This page lists every option of `BetterIamOptions`, the object you pass to `betterIam()`. Each option has its own
heading with its type, default, the range enforced at startup, and a short example. Use it as a lookup table; for
advice on which options a production deployment changes, read the
[Configuration reference](/docs/operations/deployment/configuration).

Three options are required: `database`, `secret`, and `baseURL`. Every other option is optional and has a safe
default. Durations are in milliseconds unless the option name ends in `Seconds` or `Days`.

## A complete configuration

The examples below each show only the option they describe. A real instance always carries the three required
options, as in this minimal configuration:

```ts title="iam.ts"
import { betterIam } from 'better-iam';
import { sqliteAdapter } from 'better-iam/adapter-sqlite';

export const iam = betterIam({
  database: sqliteAdapter({ filename: './iam.db' }),
  secret: process.env.BETTER_IAM_SECRET!, // at least 32 characters
  baseURL: process.env.BETTER_IAM_BASE_URL!, // https, or http on localhost
});
```

When the CLI must load the same options, put them in `better-iam.config.mjs` (or `.ts`) as the default export.
`defineConfig` from `better-iam/server` types the object, or a factory that receives `{ command, env, cwd }`, and
returns it unchanged:

```ts title="better-iam.config.ts"
import { defineConfig } from 'better-iam/server';
import { postgresAdapter } from 'better-iam/adapter-postgres';

export default defineConfig(({ env = process.env } = {}) => ({
  database: postgresAdapter({ connectionString: env.DATABASE_URL! }),
  secret: env.BETTER_IAM_SECRET!,
  baseURL: env.BETTER_IAM_BASE_URL ?? 'http://localhost:3000',
}));
```

In your server, call `betterIam(await configOptions(config))` (also from `better-iam/server`) to turn a factory
into options. The CLI also reads a named `cli` export from the same module (flag defaults for its commands); that
export is CLI configuration, not a `betterIam()` option. See [CLI](/docs/concepts/cli).

## How options are validated

`betterIam()` validates the whole configuration once, when it runs. A missing required option, a value outside its
range, or an unknown key in a strict group (`clearances`) throws an `IamError` with code `INVALID_CONFIG` before
the instance exists. The message names the field, for example `sts.maxRoleSessionSeconds must be an integer from
900 to 43200` or `vault.maxValueBytes must be an integer from 16 to 1048576`. Because a misconfiguration fails at
startup, it never surfaces on the first request instead.

Options that switch on an optional module (`inference`, `ssh`, `verifiableCredentials`, `clearances`, `a2a`) leave
it off when absent. Calling one of its API methods on a deployment where it is off fails with `FEATURE_DISABLED`
(403).

| Area | Options |
| --- | --- |
| [Core](#core) | `database`, `secret`, `previousSecrets`, `baseURL`, `basePath`, `trustedOrigins` |
| [Authentication](#authentication) | `authentication` (with `rateLimits` and `passwordPolicy`), `http` |
| [Tenancy and catalog](#tenancy-and-catalog) | `hierarchy`, `permissions`, `onboarding`, `tenantDefaults`, `domains`, `hosts`, `regions` |
| [Application callbacks](#application-callbacks) | `resolveResource`, `resolveContext` |
| [Access workflows](#access-workflows) | `accessRequests`, `accessUsage` |
| [Events, audit, and telemetry](#events-audit-and-telemetry) | `events`, `auditArchive`, `observability` |
| [Extensions and protocols](#extensions-and-protocols) | `plugins`, `protocols` |
| [Temporary credentials](#temporary-credentials) | `sts` (with `jwt` and `webIdentity`) |
| [Optional modules](#optional-modules) | `inference`, `a2a`, `billing`, `ssh`, `verifiableCredentials`, `clearances`, `vault`, `signals` |

## Core

The core options say where data is stored, which secret protects it, and where the deployment is reachable.

### database

| Type | Default | Required |
| --- | --- | --- |
| `IamStore` | none | yes |

The storage adapter every IAM record is written to. Use `postgresAdapter` from `better-iam/adapter-postgres`,
`sqliteAdapter` from `better-iam/adapter-sqlite`, `libsqlAdapter` from `better-iam/adapter-libsql`, or your own
implementation of the `IamStore` contract. A missing value fails with `INVALID_CONFIG` (`database is required`).
See [Databases](/docs/databases).

```ts title="iam.ts"
import { betterIam } from 'better-iam';
import { postgresAdapter } from 'better-iam/adapter-postgres';

export const iam = betterIam({
  database: postgresAdapter({ connectionString: process.env.DATABASE_URL! }),
  // ...secret, baseURL
});
```

### secret

| Type | Default | Required |
| --- | --- | --- |
| `string` | none | yes, at least 32 characters |

The deployment secret. It encrypts the secrets Better IAM stores (authenticator secrets, webhook secrets, pending
outbox deliveries, and modules' sealed values such as vault secrets, KMS key material, SSH CA keys, and inference
provider keys), keys the digests of one-time challenges, and derives the service-assertion signing key. Keep it stable across restarts and
processes: replacing it outright makes enrolled factors and webhook secrets unusable. Rotate it with
[`previousSecrets`](#previoussecrets). It does not sign session JWTs, which use [`sts.jwt`](#stsjwt).

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  secret: process.env.BETTER_IAM_SECRET!,
  // ...database, baseURL
});
```

### previousSecrets

| Type | Default | Range |
| --- | --- | --- |
| `string[]` | none | at most 5 distinct values, each at least 32 characters, none equal to `secret` |

Deployment secrets being rotated out. Everything they sealed or signed keeps working while new values use `secret`.
`iam.rotateSecrets()` re-seals stored values with the current secret, after which you remove the old ones. See
[Secrets and keys](/docs/operations/deployment/secrets).

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  secret: process.env.BETTER_IAM_SECRET!,
  previousSecrets: [process.env.BETTER_IAM_PREVIOUS_SECRET!],
  // ...database, baseURL
});
```

### baseURL

| Type | Default | Required |
| --- | --- | --- |
| `string` | none | yes |

The public URL people and clients reach the deployment at. It must use `https:`, except on the loopback hosts
`localhost`, `127.0.0.1`, and `[::1]` (`INVALID_CONFIG`: `HTTPS is required outside localhost`). Its origin is
always a trusted origin. On HTTPS the session cookie is named `__Host-better-iam.session`; on plain HTTP it is
`better-iam.session`.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  baseURL: 'https://identity.example.com',
  // ...database, secret
});
```

### basePath

| Type | Default |
| --- | --- |
| `string` | `'/api/iam'` |

The URL path the HTTP handler answers under. It must start with `/`, contain only letters, digits, underscores,
hyphens, and slashes, and not end with `/` (`INVALID_CONFIG`: `Invalid basePath`). Browser clients and framework
integrations must use the same path.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  basePath: '/auth',
  // ...database, secret, baseURL
});
```

### trustedOrigins

| Type | Default |
| --- | --- |
| `string[]` | the `baseURL` origin only |

Additional exact origins (scheme, host, and port) allowed to call the handler from a browser. Add your application's
origin when it differs from `baseURL`, for example `https://app.example.com` calling
`https://identity.example.com`. Each entry must be an exact origin with no path (`INVALID_CONFIG`:
`Trusted origins must be exact origins`). Browser requests from any other `Origin` are refused with
`UNTRUSTED_ORIGIN`.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  baseURL: 'https://identity.example.com',
  trustedOrigins: ['https://app.example.com'],
  // ...database, secret
});
```

## Authentication

### authentication

| Type | Default |
| --- | --- |
| `Omit<AuthOptions, 'store' \| 'secret' \| 'previousSecrets' \| 'baseURL' \| 'trustedOrigins'>` | `{}` |

How people sign in, how sessions behave, and how email and SMS leave the system. `store`, `secret`,
`previousSecrets`, `baseURL`, and `trustedOrigins` come from the top level. The server wires `onAudit` and
`deliverWebhook` itself; use [`events`](#events) to receive events or replace the webhook transport.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `appName` | `string` | `'Better IAM'` | Your product name as the issuer in authenticator-app labels and the default passkey `rpName`. Built-in email templates take their own `appName` (`TemplateOptions` in `better-iam/auth/templates`). |
| `signUpEnabled` | `boolean` | `false` | Lets anyone create an account with email and password. |
| `requireEmailVerification` | `boolean` | `signUpEnabled` | Refuses sign-in until the address is verified. Needs `sendEmail`. |
| `emailPassword` | `boolean` | `true` | Password sign-in, sign-up, and reset. `false` disables all three. |
| `passwordlessEmail` | `boolean` | `false` | Magic links and one-time email codes. Needs `sendEmail`. |
| `passwordlessSms` | `boolean` | `false` | One-time SMS codes. Needs `sendSms`. |
| `sendEmail` | `(message: DeliveryMessage) => Promise<void>` | none | Your email transport, called by the outbox outside the write transaction. Throw to retry; deduplicate by `message.id`. |
| `sendSms` | `(message: DeliveryMessage) => Promise<void>` | none | Your SMS transport, with the same contract as `sendEmail`. |
| `maxDeliveryAttempts` | `number` | `25` | Failed attempts (1 to 1000) before the outbox abandons a message. |
| `sessionLifetimeMs` | `number` | 7 days | Absolute session lifetime, one minute to thirty days. |
| `sessionIdleTimeoutMs` | `number` | the smaller of the lifetime and 1 day | Idle timeout, one minute to the absolute lifetime. |
| `recentAuthenticationMs` | `number` | 5 minutes | How long a sign-in counts as recent for sensitive operations, one second to fifteen minutes. |
| `trustedDeviceLifetimeMs` | `number` | 30 days | How long "remember this device" skips MFA. `0` disables it; otherwise one minute to 365 days. |
| `signInNotifications` | `boolean` | `false` | Queues a `new-sign-in` email when a session starts from a client none of the person's live sessions or remembered devices has used. Tenants override it with `notifyNewSignIn`. |
| `mfaEmailCodes` | `boolean` | `false` | Lets people without an authenticator satisfy MFA with an emailed one-time code. Never applies to root administrators. Tenants override it. |
| `failedSignInAlerts` | `number` | `0` | Emails a `sign-in-failures` alert after this many failed attempts since the last sign-in. `0` disables it; at most 1000; needs `sendEmail`. |
| `rateLimits` | `RateLimitOptions` | see [below](#authenticationratelimits) | Attempt limits for authentication flows. |
| `requireMfa` | `(tenant: Tenant, identity: Identity) => boolean \| Promise<boolean>` | none | A deployment-wide rule deciding who must complete MFA. Tenant policies add to it. |
| `passkeys` | `{ rpID: string; rpName?: string }` | off | Enables WebAuthn passkeys. `rpID` must equal, or be a parent domain of, the host of every trusted origin. `rpName` defaults to `appName`. |
| `passwordPolicy` | `PasswordPolicyOptions` | see [below](#authenticationpasswordpolicy) | Deployment-wide password screening. |
| `now` | `() => number` | `Date.now` | Replaces the clock, for deterministic tests. The whole server uses it. |

`DeliveryMessage` carries `id`, `tenantId`, `to`, `template`, `payload` (string values), and, when
[`hosts`](#hosts) or [`regions`](#regions) are configured, `signInUrl` with the organization's own sign-in address.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  authentication: {
    appName: 'Acme',
    passwordlessEmail: true,
    sessionLifetimeMs: 24 * 60 * 60_000,
    passkeys: { rpID: 'example.com' },
    sendEmail: async (message) => {
      await mailer.send({ id: message.id, to: message.to, template: message.template, data: message.payload });
    },
  },
  // ...database, secret, baseURL
});
```

`mailer` stands for your own email provider client. See [Email and SMS delivery](/docs/concepts/email-and-sms) and
[Sessions](/docs/authentication/sessions).

### authentication.rateLimits

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `attempts` | `number` | `10` | Attempts per window for ordinary flows such as password sign-in (1 to 100000). |
| `sensitiveAttempts` | `number` | `5` | Attempts per window for MFA, recovery, and delivery requests (1 to 100000). |
| `windowMs` | `number` | 15 minutes | The rolling window, one second to 24 hours. |
| `ipAttempts` | `number` | `0` | Attempts per window from one client IP across every authentication flow of a tenant (0 to 1000000; `0` disables it). Needs a recorded IP from [`http.clientInfo`](#http). |
| `limiter` | `RateLimiter` | counters in the IAM database | Replaces the counter store. Implement `consume()`, and optionally `reset()` so administrators can unlock accounts. |

A refused attempt fails with `RATE_LIMITED` (429). `createMemoryRateLimiter()` and `createStoreRateLimiter(store)`
from `better-iam/auth` are the built-in limiters; the in-memory one suits single-process deployments and tests.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  authentication: {
    rateLimits: { attempts: 5, windowMs: 10 * 60_000, ipAttempts: 200 },
  },
  // ...database, secret, baseURL
});
```

### authentication.passwordPolicy

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `blockCommonPasswords` | `boolean` | `true` | Rejects well-known, keyboard-walk, sequential, and low-variety passwords from a short built-in list. |
| `isBreached` | `(password: string) => Promise<boolean>` | none | Returns `true` when the password appears in a breach corpus. |
| `check` | `(password, { tenantId, identity? }) => string \| undefined \| Promise<string \| undefined>` | none | Your own rule: return a message to reject the password, or nothing to accept it. |

Passwords are hashed with Argon2id and need at least 12 characters whatever this policy says; tenant policies add
their own rules (`minPasswordLength`, `passwordHistory`, and others) on top. `pwnedPasswords()` from
`better-iam/auth` is a Have I Been Pwned client for `isBreached` that sends only a five-character SHA-1 prefix.

```ts title="iam.ts"
import { betterIam } from 'better-iam';
import { pwnedPasswords } from 'better-iam/auth';

export const iam = betterIam({
  authentication: {
    passwordPolicy: {
      isBreached: pwnedPasswords(),
      check: (password) => (/acme/i.test(password) ? 'Do not use the company name' : undefined),
    },
  },
  // ...database, secret, baseURL
});
```

### http

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `clientInfo` | `(request: Request) => SessionClientInfo \| undefined` | records the `User-Agent` header only | Derives the client details (`ip`, `userAgent`, `label`) recorded on sessions a request issues. |
| `cookieSameSite` | `'lax' \| 'strict'` | `'lax'` | `SameSite` of the session and device cookies. |
| `persistentCookies` | `boolean` | `true` | `true` sets the cookie `Max-Age` to the session's remaining lifetime; `false` issues browser-session cookies. A request overrides it with the `X-Better-IAM-Persistent: 1` or `0` header. |

Read the client IP only from a header that a proxy you control sets; never trust `X-Forwarded-For` otherwise. Tenant
IP allowlists, IP-bound sessions, `rateLimits.ipAttempts`, and new-sign-in notifications all depend on a recorded
IP. Invalid values fail with `http.cookieSameSite must be lax or strict` or `http.persistentCookies must be a
boolean`.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  http: {
    clientInfo: (request) => ({
      ip: request.headers.get('x-real-ip') ?? undefined, // set by your own reverse proxy
      userAgent: request.headers.get('user-agent') ?? undefined,
    }),
    cookieSameSite: 'strict',
  },
  // ...database, secret, baseURL
});
```

See [HTTP handler](/docs/authentication/http).

## Tenancy and catalog

These options describe the shape of your product: which kinds of tenants exist, which actions and resource types
policies can name, how people join, and what every new tenant starts with.

### hierarchy

| Type | Default |
| --- | --- |
| `{ types: Record<string, { allowedChildren: string[] }>; maxDepth?: number }` | `root` → `organization` → `project`, `maxDepth` 8 |

The kinds of tenants and which children each may have. It must define `root`; every allowed child must be a
defined type other than `root`; `maxDepth` is 1 to 100.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  hierarchy: {
    types: {
      root: { allowedChildren: ['reseller'] },
      reseller: { allowedChildren: ['customer'] },
      customer: { allowedChildren: ['workspace'] },
      workspace: { allowedChildren: [] },
    },
    maxDepth: 6,
  },
  // ...database, secret, baseURL
});
```

See [Tenants and identities](/docs/concepts/tenants-and-identities).

### permissions

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `mode` | `'catalog' \| 'tenant-defined'` | `'catalog'` | `catalog`: only you declare actions and resource types. `tenant-defined`: tenants may also register their own. |
| `actions` | `string[]` | none | Product actions not tied to a declared resource type, such as `billing:export`. |
| `resourceTypes` | `Record<string, ResourceTypeDefinition>` | none | Your resource types. Declaring any makes policy validation check resource patterns against them. |
| `identityAttributes` | `Record<string, 'string' \| 'number' \| 'boolean'>` | none | Typed attributes administrators may set on identities, exposed to policies as `principal.{name}`. Names cannot shadow built-in principal keys. |

A `ResourceTypeDefinition` has:

| Field | Type | Description |
| --- | --- | --- |
| `description` | `string` | Shown to administrators. |
| `actions` | `string[]` | Fully qualified actions for this type; they join the permission catalog. |
| `attributes` | `Record<string, 'string' \| 'number' \| 'boolean'>` | Attribute schema exposed to conditions as `resource.{name}`. |
| `parent` | `string` | Parent resource type, for hierarchical resources. |
| `managed` | `boolean` | Registered with IAM (`resources.register`) and resolved from its registry instead of `resolveResource`. |
| `relations` | `string[]` | Relation names (such as `viewer`, `editor`) identities and groups may hold on resources of this type. |

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  permissions: {
    actions: ['billing:export'],
    resourceTypes: {
      document: {
        actions: ['documents:read', 'documents:write'],
        attributes: { ownerId: 'string' },
        relations: ['viewer', 'editor'],
      },
      project: { managed: true, actions: ['projects:read', 'projects:manage'] },
    },
    identityAttributes: { department: 'string' },
  },
  // ...database, secret, baseURL
});
```

See [The permission catalog](/docs/authorization/catalog).

### onboarding

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `mode` | `'invitation' \| 'linked'` | `'invitation'` | `invitation` creates a separate identity per tenant. `linked` also lets people connect accounts they hold in several tenants through an explicit, recently authenticated link. |
| `invitationLifetimeMs` | `number` | 1 day (`86400000`) | How long owner and member invitation links stay valid. |

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  onboarding: { mode: 'linked', invitationLifetimeMs: 7 * 86_400_000 },
  // ...database, secret, baseURL
});
```

### tenantDefaults

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `limits` | `TenantLimits` | none | Plan limits stamped on every tenant `tenants.create` creates: `identities`, `serviceAccounts`, `agents`, `groups`, `roles`, `policies`, `resources`, `webhooks`. |
| `authPolicy` | `TenantAuthPolicy` | none | An authentication policy stamped on every new tenant, such as `{ requireMfa: true }`. |

Both are validated at construction; errors are prefixed with `tenantDefaults:`. Creating past a limit fails with
`LIMIT_EXCEEDED`. See [Tenant authentication policy](/docs/authentication/tenant-policy) for every
`TenantAuthPolicy` field.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  tenantDefaults: {
    limits: { identities: 50, serviceAccounts: 5, webhooks: 3 },
    authPolicy: { requireMfa: true, sessionLifetimeMs: 12 * 60 * 60_000 },
  },
  // ...database, secret, baseURL
});
```

### domains

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `resolveTxt` | `(hostname: string) => Promise<string[][]>` | `resolveTxt` from `node:dns/promises` | The DNS TXT lookup that proves control of an email domain or custom hostname. |
| `recordName` | `string` | `'_better-iam-challenge'` | The label under the domain that holds the TXT record. Must be a single DNS label. |
| `blockedDomains` | `string[]` | widely used consumer mailbox providers (`gmail.com`, `outlook.com`, ...) | Domains no tenant may claim, compared exactly. Supplying it replaces the default list. |

These settings serve the `domains` API group (verified email domains and home-realm discovery) and custom
hostnames.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  domains: { recordName: '_acme-verify' },
  // ...database, secret, baseURL
});
```

See [Enterprise onboarding](/docs/federation/enterprise-onboarding).

### hosts

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `patterns` | `string[]` | `[]` | Up to 16 hostname templates. Each contains `{tenant}` (the organization's alias) exactly once and `{region}` at most once. The first is the canonical address used in sign-in URLs and email links. |
| `customHostnames` | `boolean` | `false` | Lets organizations verify hostnames of their own with a DNS TXT record (`hostnames` API group). |
| `cnameTarget` | `string` | none | The hostname organizations point their custom hostname at with a CNAME, shown in the setup instructions `hostnames.add` returns. |
| `signInPath` | `string` | `'/'` | The path of your sign-in page on an organization's address. |
| `forwardedHost` | `boolean` | `false` | Reads the address from `X-Forwarded-Host` before `Host`. Enable it only behind a proxy you control. |

Requests on an organization's address are pinned to that organization. A `{region}` pattern needs the
[`regions`](#regions) option, patterns need an HTTPS `baseURL` outside localhost, and with `passkeys` configured every
pattern must sit under the passkey `rpID`.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  hosts: {
    patterns: ['{tenant}.signin.example.com'],
    customHostnames: true,
    cnameTarget: 'custom.signin.example.com',
    signInPath: '/sign-in',
  },
  // ...database, secret, baseURL
});
```

See [Sign-in addresses and regions](/docs/operations/deployment/hosts-and-regions).

### regions

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `current` | `string` | required | This deployment's region, such as `'us-east-1'`. Must be one of `regions`. |
| `regions` | `Record<string, { baseURL?: string; label?: string }>` | required | 1 to 64 regions with the base URL of each region's deployment (HTTPS outside localhost) and a display label (1 to 64 characters). |
| `locate` | `(alias: string) => Promise<string \| undefined>` | none | For regions with separate databases: returns the region an organization alias lives in when this region's database does not know it. |

Without `regions` the deployment is single-region. Sign-in for an organization homed in another region answers
`WRONG_REGION` with its sign-in URL there.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  regions: {
    current: 'eu-west-1',
    regions: {
      'eu-west-1': { baseURL: 'https://eu.identity.example.com', label: 'Europe' },
      'us-east-1': { baseURL: 'https://us.identity.example.com', label: 'United States' },
    },
  },
  // ...database, secret, baseURL
});
```

See [Multi-region deployments](/docs/guides/multi-region).

## Application callbacks

These callbacks connect authorization to your own data. They run as trusted server code during decisions.

### resolveResource

| Type | Default |
| --- | --- |
| `(reference: ResourceRef) => Promise<ResourceRef & { attributes?: Record<string, unknown>; classification?: ClassificationLabel \| null }>` | none |

Looks up an application-owned resource (a type that is not `managed`) in your trusted storage and returns its
`tenantId` and attributes, so policies can check ownership and attributes. It is required for such types: without
it, their checks fail with `RESOURCE_RESOLVER_REQUIRED`. With [`clearances`](#clearances) on, it may also return a
`classification` label, which can only raise the label IAM holds.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  resolveResource: async ({ type, id }) => {
    const document = await db.documents.find(id); // your own data access
    return { type, id, tenantId: document.tenantId, attributes: { ownerId: document.ownerId } };
  },
  // ...database, secret, baseURL
});
```

### events

| Option | Type | Default | Description |
| --- | --- | --- | --- |

### auditArchive

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `write` | `(batch: AuditArchiveBatch) => Promise<void>` | required | Stores one verified batch durably. Batches arrive in chain order per tenant; key them by `tenantId`, `fromSequence`, and `toSequence`, and reject (throw) a replacement with different content. |
| `batchSize` | `number` | `1000` | Events per batch, 1 to 10000. |
| `leaseMs` | `number` | 10 minutes | How long one run may hold a tenant before another may take over, one minute to one hour. |

Archiving runs when you call `iam.archiveAudit()`. While `auditArchive` is set, `iam.pruneAudit` deletes only
events already archived. `createJsonlAuditArchive` from `better-iam/server` is a file-based sink.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
  auditArchive: {
    write: async (batch) => {
      const key = `${batch.tenantId}/${batch.fromSequence}-${batch.toSequence}.json`;
      await bucket.putIfAbsent(key, JSON.stringify(batch)); // your object storage
    },
    batchSize: 5_000,
  },
  // ...database, secret, baseURL
});
```

### observability

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `onSpan` | `(span: IamSpan) => void` | none | Receives one span per operation, authorization query, authentication call, and HTTP request. Exceptions are ignored. |
| `metrics` | `boolean \| MetricsOptions` | off | Keeps Prometheus-style counters and latency histograms in `iam.metrics`. |

`MetricsOptions`:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `buckets` | `number[]` | `[0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10]` | Histogram bucket upper bounds in seconds, sorted ascending. A bound that is not positive throws a plain `Error` (`Metrics buckets must be positive numbers`). |

| `maxSeries` | `number` | `2000` | Distinct label sets per metric before new ones collapse into `(other)`. |
| `gauges` | `boolean` | `false` | Also reports `better_iam_outbox_messages` and `better_iam_sessions_live`, read from storage on each scrape. |

```ts title="iam.ts"
import { betterIam } from 'better-iam';

export const iam = betterIam({
```

## Extensions and protocols

### plugins

| Type | Default |
| --- | --- |
| `IamPlugin[]` | `[]` |

Plugins add actions, platform resource types, POST endpoints under `{basePath}/plugins/{pluginId}/...`, operation
hooks, policy context, migrations, and purge handlers. Construction checks for unique ids, registered endpoint

`better-iam/projects` is the reference plugin.

| Field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Unique plugin id. |

### protocols

| Type | Default |
| --- | --- |
| `ProtocolMount[]` | `[]` |

Raw request handlers consulted before the IAM routes. A `ProtocolMount` has an optional
`handle(request: Request): Promise<Response | undefined>` and an optional `nodeHandler(req, res)`; returning

`iam.useProtocol(service)` after construction instead of listing them here.

```ts title="iam.ts"
import { betterIam } from 'better-iam';

    {
      handle: async (request) =>
        new URL(request.url).pathname === '/.well-known/acme-status'

          : undefined,
    },
  ],
  // ...database, secret, baseURL
});
```

### sts.jwt

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `signingKeys` | `JWK[]` | required | 1 to 10 private JWKs: `kty: 'OKP', crv: 'Ed25519', alg: 'EdDSA'` or `kty: 'EC', crv: 'P-256', alg: 'ES256'`, each with a unique `kid` (1 to 64 of `A-Z a-z 0-9 . _ -`), `use` absent or `'sig'`, `key_ops` absent or including `'sign'`. |

## Optional modules

Each option in this section turns on, or tunes, one feature module. `inference`, `a2a`, `ssh`,
`verifiableCredentials`, and `clearances` are off until set; while off, their methods answer `FEATURE_DISABLED`.
`billing`, `vault`, and `signals` are always available; their options tune or extend them.

| Type | Default |
| --- | --- |
| `boolean \| InferenceOptions` | off |

Inference access control for AI models: the `model` resource type and the `inference:invoke` action, the
`inference` API group (providers with sealed keys, models, budgets, usage), and `iam.inference` (checks, metering,
and the gateway). `true` enables it with defaults.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `allowCustomBaseUrls` | `boolean` | `false` | Lets organizations below the root point a provider at a custom base URL. Otherwise only a root administrator may. |

| `allowInsecureLocalhost` | `boolean` | `false` | Lets base URLs use http on loopback hosts. Development and tests only. |
| `allowPrivateNetworks` | `boolean` | `false` | Lets organization-chosen base URLs reach private and reserved addresses. Base URLs of the root tenant's providers are never restricted. |

| Code | When |
| --- | --- |
