# Standalone server configuration (`better-iam.json`)

Every better-iam server implementation (TypeScript, Rust, Go) can run as a standalone HTTP server configured by one
JSON file. The format is `BetterIamOptions` (`packages/server/src/options.ts`) with every JSON-representable member
spelled exactly as in TypeScript, plus three members that replace what a JSON file cannot hold: `store` (the
`database` object), `delivery` (the email, SMS, webhook and event callbacks) and `resolveResource` (a resolver
function); in conformance mode, application callbacks can also be scripted (rule 3). The schema is [`config.schema.json`](config.schema.json); the TypeScript reader is
`scripts/conformance/lib/config.mjs` (`optionsFromConfig`), and its inverse (`configFromOptions`) is what the trace
recorder uses to describe each recorded instance.

```json
{
  "$schema": "./config.schema.json",
  "store": { "kind": "sqlite", "path": "./iam.db" },
  "secret": { "env": "BETTER_IAM_SECRET" },
  "baseURL": "https://iam.example.com",
  "basePath": "/api/iam",
  "authentication": { "sessionLifetimeMs": 604800000, "passkeys": { "rpID": "example.com" } },
  "delivery": { "email": { "kind": "http", "url": "https://mailer.internal/send" } },
  "permissions": { "actions": ["documents:read", "documents:write"] },
  "resolveResource": { "kind": "echo" }
}
```

## Starting a server

```
node scripts/conformance/serve.mjs --config better-iam.json --port 4100 [--host 127.0.0.1] [--conformance]
better-iam-server --config better-iam.json --port 4100 [--host 127.0.0.1] [--conformance]     (Rust, Go)
```

- The server builds the instance from the file, runs `initialize()` (migrations), and serves the HTTP surface on
  `--host:--port` exactly as `iam.nodeHandler` does: `POST {basePath}/{group}/{method}`, `auth/*`, `authorize`,
  `authorizeMany`, `listAccessible`, `plugins/*`, the operational `GET` routes and the protocol mounts that options
  enable (the verifiable-credential issuer, the Shared Signals push endpoint).
- `baseURL` is the deployment's logical address (cookie names, trusted origin, token issuers); it does not have to be
  the address the server listens on.
- `--conformance` adds the test-control endpoints of [CONTROL.md](CONTROL.md), makes the `capture` delivery transport
  available, and puts both server clocks under control. Never use it in production.
- When the configuration is refused (by the file reader or by the options validation, `INVALID_CONFIG` and friends)
  the server exits with status 1 and writes one JSON line to stderr: `{"error":{"code","status","message"}}`.

## Members

| Member                                                                                                         | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `store`                                                                                                        | `{ "kind": "sqlite", "path"?, "busyTimeoutMs"?, "journalMode"?, "durability"? }` (default `{ "kind": "sqlite", "path": ":memory:" }`), `{ "kind": "postgres", "url", "poolSize"?, "lockTimeoutMs"? }`, `{ "kind": "libsql", "url", "authToken"?, "encryptionKey"?, "syncUrl"?, "syncInterval"? }`. The adapter options mirror `sqliteAdapter`, `postgresAdapter` (`url` is `connectionString`) and `libsqlAdapter`.                                                                                                                                                   |
| `secret`, `previousSecrets`                                                                                    | A string, or `{ "env": "NAME" }` to read an environment variable (also accepted for `store.url`, `store.authToken`, `store.encryptionKey`).                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `baseURL`, `basePath`, `trustedOrigins`                                                                        | As in `BetterIamOptions`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `authentication`                                                                                               | `AuthOptions` without the members the top level or `delivery` carries: `appName`, `signUpEnabled`, `requireEmailVerification`, `emailPassword`, `passwordlessEmail`, `passwordlessSms`, `maxDeliveryAttempts`, `sessionLifetimeMs`, `sessionIdleTimeoutMs`, `recentAuthenticationMs`, `trustedDeviceLifetimeMs`, `signInNotifications`, `mfaEmailCodes`, `failedSignInAlerts`, `rateLimits` (`attempts`, `sensitiveAttempts`, `windowMs`, `ipAttempts`), `passkeys` (`rpID`, `rpName`), `passwordPolicy` (`blockCommonPasswords`).                                    |
| `delivery`                                                                                                     | Channels `email` (`authentication.sendEmail`), `sms` (`authentication.sendSms`), `webhook` (`events.deliverWebhook`), `events` (`events.onEvent`). Each is `{ "kind": "capture" }` (conformance mode only: kept for the control endpoints), `{ "kind": "log" }` (a JSON line `{"delivery": channel, "message": …}` on stdout) or `{ "kind": "http", "url", "headers"?, "timeoutMs"? }` (POST `{"kind": channel, "message": …}`; a non-2xx answer fails the delivery and the outbox retries it). An absent channel is not configured, exactly like an absent callback. |
| `resolveResource`                                                                                              | `{ "kind": "echo" }`: the resolver that trusts the reference as given (`async (reference) => reference`), or `{ "$scripted": true }` (rule 3). Absent: no resolver (product resource types then need one, as in-process). `resolveContext` takes only `{ "$scripted": true }`.                                                                                                                                                                                                                                                                                        |
| `hierarchy`, `permissions`, `onboarding`, `accessRequests`, `tenantDefaults`, `hosts`, `signals`, `clearances` | As in `BetterIamOptions`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `events`                                                                                                       | `webhookTimeoutMs`, `allowPrivateNetworks` (the callbacks are `delivery.webhook` and `delivery.events`).                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `observability`                                                                                                | `metrics` (`true` or `{ buckets, bearerToken, maxSeries, gauges }`); `onSpan` has no JSON form.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `accessUsage`, `inference`, `ssh`, `verifiableCredentials`                                                     | `true`/`false` or their options object, as in-process.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `a2a`, `sts`                                                                                                   | As in-process; JWKs are written as JSON (RFC 7517). `sts.webIdentity.fetchJson` only as a scripted callback (rule 3).                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `billing`                                                                                                      | As in-process (`issuer` is an object).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `vault`                                                                                                        | `maxValueBytes`, `maxSecretsPerTenant`, `accessRetentionDays`, `callTimeoutMs`; rotators and engines only as scripted callbacks (rule 3).                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `auditArchive`                                                                                                 | `batchSize`, `leaseMs`, and `write` as a scripted callback (rule 3, conformance mode only).                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `http`                                                                                                         | `cookieSameSite`, `persistentCookies`, and `clientInfo` (`{ "userAgent"?: true, "ipHeader"?, "labelHeader"?, "ipValue"?: "first" or "whole" }`): the JSON form of `http.clientInfo(request)`, which records the User-Agent (unless `false`), the first comma-separated entry of `ipHeader`, trimmed (or with `ipValue: "whole"` the header as sent) as the client IP, and `labelHeader` as the device label; it returns no client when none of them is present. Absent: the default (User-Agent only).                                                                |
| `domains`                                                                                                      | `recordName`, `blockedDomains`; `resolveTxt` only as a scripted callback (rule 3); otherwise DNS is used.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `regions`                                                                                                      | `current`, `regions`; `locate` only as a scripted callback (rule 3).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Rules every implementation follows:

1. **Unknown top-level members are refused** (`INVALID_CONFIG`, `Invalid better-iam.json: unknown member "x"`).
   Inside the members, validation is exactly that of the in-process options (the same `INVALID_CONFIG` codes and
   messages, in the same order); the schema describes shapes and is advisory for authoring.
2. **Defaults are those of the in-process options.** A member that is absent behaves as the absent option.
3. **Scripted callbacks (conformance mode only).** These application callbacks may be written as
   `{"$scripted": true}`: `resolveResource`, `resolveContext`, `authentication.requireMfa`,
   `authentication.passwordPolicy.isBreached` / `check`, `domains.resolveTxt`, `regions.locate`,
   `sts.webIdentity.fetchJson`, `vault.rotators.<name>.rotate`, `vault.engines.<name>.issue` / `revoke` / `renew`, `auditArchive.write`.
   The server then answers each call from the script the runner provides (CONTROL.md, "Script"). The marker anywhere
   else is refused (`Invalid better-iam.json: <path> cannot be scripted`), and without `--conformance` it is refused
   too (`Invalid better-iam.json: <path> is scripted, which needs the server's conformance mode`). `resolveContext` has
   no other JSON form.
4. **No other function-valued option has a JSON form**: `plugins`, `protocols`,
   `authentication.rateLimits.limiter`, an `http.clientInfo` function that does more than copy request headers (the
   recorder writes one that only copies them as the header mapping above, after checking it on probe requests; an
   empty client counts as none), `observability.onSpan`, and the callbacks of rule 3 outside conformance mode. A recorded instance that used one of
   them is marked `replayable: false` (FORMAT.md).
