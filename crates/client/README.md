# better-iam-client

The typed client of the [Better IAM](https://github.com/Better-IAM/better-iam) HTTP API for Rust, the port of
`@better-iam/client`. Every route of the API is a method with the request and result types of `better-iam-types`,
and calls behave exactly like the TypeScript client: `POST {basePath}/{group}/{method}` with a JSON body, the CSRF
headers the server requires, a bearer token read at each request and refused locally when it cannot be one the
server issues, structured `IamClientError`s that keep the server's code without echoing response bodies,
`on_unauthenticated` for sessions that ended, an optional single retry of rate-limited calls (cancellable with an
`AbortSignal`), and `X-Request-Id` tagging.

```rust,ignore
use better_iam_client::{create_iam_client, ClientOptions};
use better_iam_types::api::auth;

let client = create_iam_client(ClientOptions::new("https://app.example.com").token(token))?;
let session = client.auth().get_session().await?;
let decision = client.authorize(input).await?;
let page: serde_json::Value = client.request("plugins/reporting/summary", &body).await?; // plugin endpoints
```

- `session`: a framework-neutral session store (`create_session_store`).
- `device`: registered-device proofs (`create_device_prover`), ES256 over a P-256 key the prover keeps.
- Feature `default-transport` (on by default): the built-in HTTP(S) transport (hyper and rustls). Pass your own
  `Fetch` to route requests elsewhere, for example straight into a server's handler.

The per-route methods (`src/api.rs`) are generated by `scripts/spec/gen-rust-client.mjs` in the repository;
`node scripts/spec/check-generated.mjs rust-client` fails when they are stale.
