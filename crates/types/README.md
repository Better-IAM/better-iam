# better-iam-types

The typed HTTP API surface of [Better IAM](https://github.com/Better-IAM/better-iam) for Rust: every request body,
result and model type of the API, and the route table, shared by the Rust server and the Rust client. It is
generated from the OpenAPI document and route table the TypeScript implementation publishes (`spec/api/openapi.json`,
`spec/api/routes.json`), so the JSON matches the TypeScript server's member for member.

- `schemas`: one item per component schema (`Role`, `AccessPath`, `SignInResult`, ...), also re-exported at the
  crate root. Types `better-iam-core` already declares (`Tenant`, `Identity`, `AuditEvent`, `Decision`, ...) are
  re-exported from it.
- `api::<group>`: per route, `<Method>Input` (the request body), `<Method>Output` (the `data` of the answer) and a
  marker type implementing `routes::Operation`.
- `routes`: `ROUTES` (path, group, method, public or authenticated, how the router calls it, cookies), `lookup`
  and `visit` (dispatch a path to its typed operation).

Absent members, `null` and values stay distinct (`Option`, `Option<Option<T>>`, `Option<serde_json::Value>` for
members of any type), and `to_json_string` writes numbers the JavaScript way, so a value serializes to the bytes the
TypeScript server would send.

```rust,ignore
use better_iam_types::api::roles;
use better_iam_types::routes::Operation;

let input = roles::CreateInput { tenant_id: tenant.into(), name: "editor".into(), ..Default::default() };
let path = <roles::Create as Operation>::ROUTE.path; // "roles/create"
let body = better_iam_types::to_json_string(&input)?;
```

Everything except `lib.rs`, `macros.rs` and `runtime.rs` is generated by `scripts/spec/gen-rust-types.mjs` in the
repository; `node scripts/spec/check-generated.mjs rust` fails when the checked-in files are stale.
